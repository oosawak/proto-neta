- 元の情報: Maki@Sunwood AI Labs.（@hAru_mAki_ch）のX投稿（2026-11-25）。作者は、MuseとGoogleの機能だけで作ったサーバーレス家計簿で以前話題になっていた人。一次情報は GitHub Sunwood-ai-labs/bambu-cli のREADMEで確認。MITライセンス、Python 3.10以上、リポジトリ公開は2026-11-24。
- 仕組み: Bambu Studio CLI（ヘッドレススライス）と bambulabs-api（LAN制御）を組み合わせたもの。コマンドは config／slice／upload／print／status／pause／resume／stop／light／gcode。print に .stl や .3mf を渡すと、スライス→FTPS（ポート990）で本体へ転送→MQTT（8883）で印刷開始までを一括でやる。status --json で進捗・レイヤー・ノズルやベッドの温度・残り時間・エラーが機械可読に取れる。
- 前提: プリンター側で LAN Only Mode と Developer Mode を有効化し、IPアドレス・Access Code・シリアル番号を設定ファイル（~/.bambu-cli/config.json）に保存する。検証環境は A1 mini＋Windows＋Bambu Studio v02.09.01.70。
- ハマりどころ（投稿とREADMEの両方に明記）: FTPSの990は通るのにMQTTの8883がタイムアウトする場合は、A1 mini のMQTT同時接続数がごく小さいためで、別PCで開いている Bambu Studio を閉じると開通する。
- 面白いところ: 「AIエージェントから実機を直接動かす」ための道具立てが、状態取得のJSON化まで含めて揃っているところ。本人の文脈では、trellis.cpp等で作った3Dモデル（GLB）を印刷可能な形にして実物化する出口として、また「エージェントに物理側の手を付ける」系譜（登録済みの「予備スマホをClaudeの手にする」等）と並ぶ。
- 注意点: 公開直後で利用実績はまだ少ない。対応は実質A1 mini検証のみで、他機種は試作時に確認が要る。Access Codeを扱うので、設定ファイルの置き場所と公開範囲には注意。
